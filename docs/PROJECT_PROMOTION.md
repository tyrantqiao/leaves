# Leaves：把每一次出发，变成可以回看的足迹

> Leaves 是一个 Windows 优先的个人出行记录软件。它不试图替代订票平台、航班雷达或铁路调度工具，而是专注于一件更贴近日常的事：用尽可能少的输入，把一次移动可靠地记录下来，并在之后用地图、时间线、统计和成就重新看见自己的生活轨迹。

![Leaves 首页航班记录](https://github.com/tyrantqiao/leaves/blob/main/docs/images/leaves-home-flight.png?raw=1)

## 为什么需要 Leaves

我们经常记得一次旅行的目的地，却很少真正保存移动本身：哪天出发、坐了哪趟车、从哪个站到哪个站、飞过哪条航线、这一年到底跨过多少城市。等到想回顾时，这些信息分散在 12306 订单、航司短信、日历、相册、聊天记录和脑子里，找起来费力，也很难形成完整的个人足迹。

Leaves 想解决的不是“买票”问题，而是“留下记录”问题。

它把出行登记做成一个轻量入口：你可以输入航班号、铁路车次号、城市路线，也可以在信息不完整时直接手动补充。记录保存后，Leaves 会把它放进地图、近期行程、数据看板和成就体系里。久而久之，你看到的不只是几条交通记录，而是一份属于自己的移动年轮。

![多交通方式行程记录](https://github.com/tyrantqiao/leaves/blob/main/docs/images/leaves-home-multimode.png?raw=1)

## 一屏完成核心回顾

Leaves 的首页不是营销页，而是一个可以立刻使用的应用屏幕。当前桌面原型把最常用的三件事放在同一屏：

- 顶部快速登记：输入车次、航班或路线，快速生成行程草稿。
- 中央地图 Hero：当前选中的行程会直接在地图上展示路线和端点。
- 底部近期行程条：用最短路径切换最近记录，快速回到某一次出发。

这样的布局尤其适合个人长期使用。打开软件时，你不需要先进入复杂菜单，也不需要在多个页面之间来回跳。记录、查看、回顾都从第一屏开始。

![首页桌面视图](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/05-home-desktop.png?raw=1)

## 快速登记：从一个输入框开始

Leaves 的登记流程遵循一个原则：少填表。

你可以输入：

```text
CA1234
G1234
上海虹桥到杭州东
北京南 -> 南京南
```

系统会尝试识别交通方式，并生成可编辑的行程草稿。当前原型已支持航班、铁路、道路、轮船等多种方式的登记与展示。对于信息不完整的记录，Leaves 会让用户补齐必要字段，而不是用不可信的默认值替你做决定。

![航班登记预览](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/03-flight-preview-desktop.png?raw=1)

### 航班：坚持手动确认

Leaves 的航班登记目前采用手动流程：航司、航班号、日期、起飞地、降落地、起降时间都由用户确认。这样做看起来克制，但对个人记录工具来说非常重要。航班号通常需要日期才能准确定位，外部数据源也存在额度、稳定性和准确性问题。Leaves 更倾向于让用户掌握最终记录，而不是把个人行程托付给一个随时可能失效的远端查询。

![移动端航班表单](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/09-flight-form-360x640.png?raw=1)

### 铁路：有辅助，也有兜底

铁路场景下，Leaves 当前原型提供了车站搜索、车次号转换、经停站查询和中转换乘能力。这些能力通过本地服务封装为同源 API，前端不直接跨域访问 12306。

如果查询成功，用户可以用真实经停站和时刻辅助填写。如果查询失败，流程不会中断，仍然可以保存手动记录。对一个本地优先的个人工具来说，这种“可增强，但不依赖”的设计非常关键。

![铁路手动兜底流程](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/04-rail-fallback-desktop.png?raw=1)

## 地图：让记录重新变成路线

很多出行记录的价值，不在表格里，而在地图上。

Leaves 使用地图来呈现每一次移动：航班用弧线表示，铁路、道路和轮船用近似路线表示，城市与站点以点位呈现。点击近期行程或时间线记录时，地图会聚焦到对应路线，让一次看似普通的移动重新变得具体。

这也让 Leaves 不只是一个“记账式”的工具。它更像一个个人足迹容器：你能看到今年去了哪里、常走哪条线、从哪些城市反复出发，又在哪些地方留下了新的点。

![移动端首页地图](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/07-home-390x740.png?raw=1)

## 数据看板：把一年走过的路算清楚

当记录逐渐变多，Leaves 会把行程转化成可回看的统计：

| 维度 | 可以看到什么 |
| --- | --- |
| 里程 | 已完成行程累计距离，估算里程会明确标注 |
| 城市 | 去过、经过、反复访问的城市数量 |
| 方式 | 航班、铁路、道路、轮船等交通方式占比 |
| 时间 | 按月份和近期动态回顾移动节奏 |
| 状态 | 区分已完成、计划中、草稿等不同记录 |

这些统计不是为了制造复杂报表，而是为了帮助用户在年末、旅行后、换城市生活后，重新看见那些曾经只是“赶路”的时刻。

![Leaves 数据看板](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/10-dashboard-desktop.png?raw=1)

## 成就系统：给长期记录一点回响

Leaves 还提供了轻量成就系统，根据行程数量、交通方式、城市数量和累计里程解锁成就。它不是强迫用户打卡，而是给长期记录一个温和的反馈。

比如第一次记录航班、累计抵达多个城市、完成多种交通方式组合，这些原本散落在生活里的片段，会在成就页中被重新点亮。

![Leaves 成就系统](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/11-achievements-desktop.png?raw=1)

## 账号隔离与本地优先

Leaves 的当前原型已经加入登录与注册入口，并保持账号级行程隔离。每个账号看到自己的记录，浏览器本地缓存和服务端本地文件也按账号区分，避免不同用户的数据混在一起。

同时，Leaves 保留本地导入导出能力：

- 导出 Leaves JSON，备份当前账号的全部行程。
- 导入 Leaves JSON，恢复或迁移个人记录。
- 导入 12306 积分明细提取出的 CSV，将铁路票据追加为行程。

这套策略让 Leaves 更接近一个可信的个人数据工具：数据先属于用户自己，再考虑外部补全和未来同步。

![登录页](https://github.com/tyrantqiao/leaves/blob/main/docs/images/ux-review-20260909/01-login-desktop.png?raw=1)

## 为移动窄屏认真打磨

虽然 Leaves 是 Windows 优先项目，但当前原型已经针对 360 到 430 px 宽度、640 到 740 px 高度的手机视口做过重点验证。移动端首页仍然保留“快速登记、地图、近期行程条”的一屏模型，登记表单则使用更适合触控的全高面板。

这意味着 Leaves 的交互思路并不局限于桌面大屏。未来如果扩展到移动辅助记录，它已经有清晰的响应式基础。

## 技术路线：从原型到桌面应用

当前可运行版本位于 `apps/desktop-prototype/`，采用 Node + 原生 HTML/CSS/JavaScript 实现。它已经验证了快速登记、地图展示、账号隔离、本地持久化、行程管理、铁路辅助、数据看板和成就页等核心体验。

后续目标是迁移到正式桌面技术栈：

- Tauri 2 作为 Windows 桌面壳。
- React + TypeScript 承载前端交互。
- SQLite 保存行程、地点、路线和必要的外部响应。
- Provider Adapter 隔离铁路、地图、文本导入等外部数据源。

这条路线的重点不是堆功能，而是把个人数据、离线可用、低输入成本和可回顾体验做扎实。

## 适合谁使用

Leaves 特别适合这些人：

- 经常出差，需要记录航班、高铁、城市和交通费用的人。
- 喜欢旅行，希望回看年度足迹和城市路线的人。
- 铁路或航空爱好者，关心车次、航线、里程和交通方式的人。
- 想要轻量备份个人行程数据，但不想把一切交给云服务的人。

如果你曾经在年末翻相册、翻订单、翻聊天记录，只为了想起“今年到底去了哪些地方”，Leaves 要做的就是把这件事变简单。

## 快速体验

项目地址：

[https://github.com/tyrantqiao/leaves](https://github.com/tyrantqiao/leaves)

本地运行：

```powershell
npm install
npm start
```

启动后访问：

```text
http://127.0.0.1:4173
```

当前版本是桌面原型，适合体验核心流程和参与产品打磨。正式 Tauri + React + SQLite 版本仍在推进中。

## 结语

Leaves 关心的是那些被我们习惯性略过的移动瞬间：清晨出发的高铁、深夜落地的航班、临时改签后的路线、周末跨城的短途、某一年突然频繁出现的城市名。

这些记录单独看很小，积累起来却是一份很私人、很真实的生活地图。

如果你也想把自己的出发、抵达和绕路都保存下来，欢迎关注 Leaves，一起把它打磨成一个长期可用、数据可靠、打开就能回到旅途里的个人出行记录工具。
