# Leaves 开发路线图

## Phase 0: 项目启动 ✅ 已完成

- ✅ 建立产品文档、架构文档、数据模型和路线图。
- ✅ 做一个无需依赖的交互原型。
- ✅ 验证快速登记、时间线、地图、详情栏这四个核心界面。

交付物：

- ✅ README
- ✅ PRD
- ✅ 技术架构
- ✅ 数据模型
- ✅ 静态桌面原型（含 Leaflet 真实地图、localStorage 持久化、编辑/删除、JSON 导入导出）

## Phase 1: Windows MVP（进行中）

目标：把原型升级为可运行的 Windows 桌面应用。

- ⏳ 初始化 Tauri + React + TypeScript 项目。
- ✅ 建立基础 UI shell：侧栏、顶部快速登记、地图区、时间线、详情栏（原型已验证，待迁移到 React）。
- ⏳ 接入 SQLite（原型暂用 localStorage 替代）。
- ⏳ 增加轻量账号体系：最多 5 个账号、注册登录、密码哈希、按账号隔离行程数据。
- ✅ 实现 trip/segment/place/geometry 的本地 CRUD（原型层：新增、内联编辑、删除、查看已完成，存储层待替换）。
- ✅ 支持本地导入导出 JSON。

验收标准：

- ✅ 可以新增、编辑、删除、查看行程（原型已验证）。
- ✅ 重启应用后数据仍存在（localStorage 已验证，待 SQLite 复核）。
- ✅ 地图能展示至少 3 种交通方式（原型已验证）。
- ⏳ 可打包分发的 Windows 安装包。

## Phase 2: 数据补全（进行中）

目标：减少用户手动输入。

- ✅ 铁路半自动补全（原型层）：登记车次后自动向 12306 查询并补全真实发到时刻；车站搜索/余票/票价/经停/换乘接口已通过本地代理可用（移植自 mcp-server-12306）。
- ⏳ 输入解析器支持航班号、铁路车次号、地点路线和自由文本（原型已支持基础识别，待增强）。
- ⏳ 接入一个航班 provider 做技术验证。
- ⏳ 支持票据截图作为附件。

验收标准：

- ✅ 输入 `G1234` 这类车次号能识别为铁路草稿。
- ✅ 输入 `CA1234` 这类航班号能生成候选草稿。
- ⏳ 用户确认后才写入正式行程（当前为登记即写入草稿）。

## Phase 3: 地图回顾和统计

目标：让用户有回看的爽感。

- 年份/月份筛选。
- 按交通方式筛选路线。
- 总里程、次数、城市、运营方、费用统计。
- 单次行程地图聚焦。
- 年度报告导出。

验收标准：

- 用户可以选择一年并看到完整足迹。
- 可以导出一张年度回顾图片或 HTML。

## Phase 4: 自动化和同步

目标：从个人本地工具变成长期可用产品。

- 云同步。
- 手机端辅助记录。
- 邮件/日历/票据自动导入。
- OCR 识别。
- Provider 管理和额度监控。
